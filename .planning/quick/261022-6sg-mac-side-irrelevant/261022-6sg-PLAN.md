<objective>
Make the Mac's physical side (left or right of the Linux screen) irrelevant to ilhop. The author has just moved the Mac to the RIGHT; `main` hardcodes "the Mac is the LEFT neighbour" in the hop direction, the landing picks, il-reset's pull-home, il-doctor, il-repro and the README.

The one source of truth is input-leap's own `$HOME/.config/InputLeap/server.conf` links section (D-1). input-leap needs it to match the desk for physical mouse crossing anyway, so ilhop derives the side from it live on every hop (D-2). No side setting is added to any ilhop config file.

Purpose: pressing the hop key lands on the other machine, ready to type, wherever the Mac sits. That is the project's core value, and right now it is broken for the author's new desk.

Output: side-aware Linux hop path (T1), side-aware Mac side with a version-mix-safe protocol (T2), `ilhop side`, a side-aware doctor and harness, and README (T3). Then a human keypress gate (final section), which this plan cannot pass on its own.

**What this is NOT (reference commit b78c9aa on branch port-01, reverted by 2779016):** port only its side mapping. Do not bring back its window-manager adapter files on either machine, the Carbon hotkey agent, the install-time side detection, or a side config key. Its adapter refactor broke hold-Alt + repeated C on the author's machine and the root cause was never found, so every hyprctl `hl.dsp.*` call and every aerospace/osascript call stays inline exactly where main has it today. Use `git show b78c9aa -- bin/il-jump bin/il-jump-listen bin/il-repro` as a reference for the mapping only.
</objective>

Design choice recorded for D-5 (the user asked for the most robust option, with reasons): the side travels on the listener's **stderr**, captured by the new pipe's `2>` into `~/.local/state/il-hop.side`. A second stdout line after `ready` would be relayed by every deployed pipe's socket listener to a client, and could kill it on EPIPE. A one-line `ready side=` breaks deployed pipes' exact-match handshake. A blocking second read in the new pipe hangs against an old listener. stderr has none of these failure modes. Two additions beyond the literal decision, both needed for D-5's "keep right working" in every version mix:
- the listener maps legacy `right` to `linux`;
- il-jump-mac sends `linux` only once the listener has proven it understands it.

`ilhop side` also kills the listener so the Mac relearns the side, which D-6 did not list but D-5's state file needs.
