    Create `~/.local/bin/il-cursortrace` as POSIX shell in `il-doctor`'s tolerant
    style — no `set -u`, no `set -e`, so one failed probe does not abort the run —
    with `$RUN` built off `XDG_RUNTIME_DIR` exactly as `il-jump:40` and
    `il-doctor:10` build it, and the `pass`/`fail`/`warn`/`head` helpers and the
    closing summary and exit code copied from `il-doctor`. Copy the `hypr()` wrapper
    verbatim from `il-jump:111-114`.

    Four modes.

    `--sample` prints one `x y` pair from `hypr cursorpos`, parsed defensively: if
    the read fails or does not look like two integers, report it as unavailable
    rather than emitting a zero, because a silently defaulted coordinate would make
    every later comparison meaningless.

    `--arm [--seconds N] [--interval MS]` truncates the trace at
    `$RUN/ilhop-cursor.trace`, then samples in a detached, bounded loop, defaulting
    to 1200 seconds at a 25 ms interval, appending one line per sample with a single
    `printf` using `>>`: a wall-clock timestamp from `date +%Y-%m-%dT%H:%M:%S.%3N%z`
    followed by x and y. Cap the trace at 512 KiB and stop sampling if it is
    reached. Print the child PID and the wall-clock expiry time on stdout so the
    next task knows whether it is still live. This script holds no `flock` and never
    opens fd 9, so it cannot interfere with `il-jump`'s single-flight lock; keep it
    that way.

    `--verdict [--since ISO]` reads the trace and reports one of three answers.
    First it locates the hop marker: the most recent `switch from "…" to "…"` line
    from `journalctl --user -u input-leap-server.service`, within the trace's window.
    That read happens after the fact, on demand, in a diagnostic tool — it is not
    the awaited journald confirmation D-15 bans, which is specifically a wait
    inside `il-jump`'s hot path. Then it compares the samples in the two seconds
    following the marker against the samples in the two seconds preceding it.
    Report FROZE when the post-marker samples are all identical while the
    pre-marker samples were not — the local pointer stopped receiving the deltas,
    which is what A1 predicts. Report TRACKED when the post-marker samples keep
    changing, which falsifies A1. Report INCONCLUSIVE when no marker was found in
    the window, when the trace has too few samples on either side, or when the
    pointer was already stationary before the marker so freezing proves nothing.
    Print the sample counts, the pre- and post-marker position ranges, and the
    marker line itself, so the verdict can be checked by a reader rather than
    taken on trust.

    `--selftest` is the control that must pass before any verdict is believed. It
    arms a three-second trace, issues a small known local delta with
    `ydotool mousemove -- 8 0`, waits, issues `ydotool mousemove -- -8 0` to put the
    pointer back, and asserts the trace contains at least two distinct positions
    spanning at least 8 pixels in x. If the sampler cannot see an 8-pixel local move
    on an uncaptured pointer, then a later frozen reading means only that the
    sampler is blind, and A1 would be neither confirmed nor falsified. Use
    `il-jump:61`'s liveness idiom to confirm `ydotool` can talk to its daemon before
    the probe, and report the reason rather than a bare failure if it cannot.

    Finish the task by arming a 1200-second trace, and print its expiry clearly —
    the next task is a checkpoint and the author may take minutes to answer.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Hyprland compositor → `il-cursortrace` via `hyprctl cursorpos` | Read-only query of the local rendered pointer position. No dispatch, no state change. |
| `input-leap-server` journal → `il-cursortrace --verdict` | Read-only, after the fact. The journal stays at `--debug INFO`; nothing here raises the log level. |
| local user → `/dev/uinput` via `ydotoold` | The `--selftest` control move is the only injection this plan performs: two 8 px relative deltas that cancel. |
| `$XDG_RUNTIME_DIR` (per-user, mode 0700, RAM-backed tmpfs) | Where the trace file lands. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-1-05 | Denial of Service | `$XDG_RUNTIME_DIR/ilhop-cursor.trace` | low | mitigate | The trace is capped at 512 KiB and the sampler is bounded to a caller-supplied duration defaulting to 1200 seconds, so an armed-and-forgotten sampler cannot fill tmpfs or outlive the session. `--arm` truncates rather than appending across runs. |
| T-1-06 | Denial of Service | `il-jump`'s single-flight lock on fd 9 | high | mitigate | A background sampler that opened fd 9 would hold the lock and make every subsequent press refuse silently — RESEARCH Pitfall 4, the bug under investigation reproduced by accident. `il-cursortrace` never opens fd 9, takes no lock and forks no subshell inside `il-jump`; the acceptance criteria assert it. |
| T-1-07 | Denial of Service | the pointer itself, during `--selftest` | low | mitigate | The control probe issues two equal and opposite 8 px relative deltas and asserts the pointer is back where it started, so a self-test cannot leave the author's pointer displaced. `ydotool mousemove -a` is never used — absolute mode is broken on this stack per `il-jump:34`. |
| T-1-08 | Information Disclosure | the cursor trace | low | accept | The trace records pointer coordinates and timestamps only — no keystrokes and no window contents. `$XDG_RUNTIME_DIR` is per-user and mode 0700. Accepted because there is nothing sensitive in a pointer coordinate. |

**Package legitimacy:** this plan installs no packages. PROJECT.md's tech-stack
constraint is POSIX shell plus the one existing C helper, so no `npm`/`pip`/`cargo`
install task exists and no package-legitimacy gate applies.
</threat_model>
